# Exercise 1: Find Guest IP, Guest Port and Remote IP Details

## Aim

To study the behavior of VirtualBox NAT networking and observe the server IP address,
client IP address, and server port when accessing the PHP application from both the
Host OS and the Guest OS.

---

## PHP Program

```php
<?php
echo "<h3>Server Infrastructure Details</h3>";
echo "VM Guest IP Address: " . $_SERVER['SERVER_ADDR'] . "<br>";
echo "Client Remote Access IP: " . $_SERVER['REMOTE_ADDR'] . "<br>";
echo "Gateway Server Port: " . $_SERVER['SERVER_PORT'];
?>
```

---

## Observations

### Access from Host OS

| Parameter | Observation |
|-----------|-------------|
| VM Guest IP Address | 10.0.2.15 |
| Client Remote Access IP | 10.0.2.2 |
| Gateway Server Port | 80 |

### Access from Guest OS

| Parameter | Observation |
|-----------|-------------|
| VM Guest IP Address | 127.0.0.1 |
| Client Remote Access IP | 127.0.0.1 |
| Gateway Server Port | 80 |

---

## Explanation

### Access from Host OS

```
Host Browser (localhost:8081)
        │
VirtualBox NAT
        │
Ubuntu VM (10.0.2.15:80)
```

- The Host browser connects to port **8081**.
- VirtualBox forwards the request to port **80** inside the Ubuntu VM.
- Therefore, the server reports its IP as **10.0.2.15**.
- The client appears as **10.0.2.2**, which is the VirtualBox NAT gateway.
- The server port remains **80**, since Nginx listens on port 80.

---

### Access from Guest OS

```
Guest Browser
      │
127.0.0.1
      │
Nginx
```

- The request never leaves the Ubuntu VM.
- Both the client and server communicate using the loopback interface.
- Hence, both addresses are reported as **127.0.0.1**.
- The server port remains **80**.

---

## Conclusion

The experiment demonstrates the effect of VirtualBox NAT and Port Forwarding.
When accessed from the Host OS, the request passes through the NAT gateway before
reaching the VM. When accessed from the Guest OS, communication occurs locally
through the loopback interface.
