# Exercise 2: Analyze Server/Process Failure

## Aim

To observe the behavior of the Nginx web server when the PHP-FPM service is unavailable and analyze the corresponding error logs.

---

## Procedure

1. Stopped the PHP-FPM service:

```bash
sudo systemctl stop php8.4-fpm
```

2. Refreshed the page:

```
http://localhost:8081/server_info.php
```

3. Observed the browser output.
4. Examined the Nginx error log.
5. Restarted the PHP-FPM service:

```bash
sudo systemctl start php8.4-fpm
```

---

## Observations

### Browser Error

**502 Bad Gateway**

### Nginx Error Log

```
connect() to unix:/var/run/php/php8.4-fpm.sock failed
(2: No such file or directory)
while connecting to upstream
```

---

## Explanation

Nginx successfully received the client request, but it could not process the PHP script because the PHP-FPM service had been stopped. Since the PHP-FPM Unix socket was unavailable, Nginx failed to establish a FastCGI connection and returned a **502 Bad Gateway** error to the client.

---

## Conclusion

This experiment demonstrates that Nginx depends on the PHP-FPM service for executing PHP scripts. If PHP-FPM is unavailable, dynamic PHP pages cannot be processed, and Nginx responds with a **502 Bad Gateway** error.
