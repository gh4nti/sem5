# Exercise 3: System Resource Utilization & Workload Monitoring

## Aim

To monitor CPU and memory utilization of the LEMP stack under workload using the `htop` utility.

---

## Procedure

1. Opened a second terminal in the Ubuntu VM.
2. Started the process monitor using:
   ```bash
   htop
   ```
3. Recorded the baseline CPU and memory usage.
4. Generated workload by executing:
   ```bash
   for i in {1..5000}; do
       curl -s http://localhost:8081/server_info.php > /dev/null
   done
   ```
5. Observed the CPU and memory utilization during request processing.

---

## Observations

| Parameter | Observation |
|-----------|-------------|
| Number of CPUs | 12 |
| Baseline CPU Usage | ~1–2% |
| Baseline Memory Usage | 1.72 GB / 7.07 GB |
| Peak Workload CPU Usage | ~10% |
| Peak Workload Memory Usage | 1.72 GB / 7.07 GB (No significant change) |
| Process with Higher CPU Utilization | **php-fpm: pool www** |

---

## Explanation

- The system remained mostly idle before the workload was generated.
- Executing 5000 HTTP requests caused a temporary increase in CPU utilization.
- Memory usage remained almost constant because the PHP script executed was lightweight and required minimal memory.
- The **php-fpm: pool www** process showed higher CPU utilization since it executes the PHP script, while **Nginx** mainly receives the request and forwards it to PHP-FPM.

---

## Conclusion

The experiment demonstrated that dynamic PHP page execution primarily utilizes the **PHP-FPM** process. Under moderate workload, CPU usage increased temporarily, while memory consumption remained nearly unchanged due to the lightweight nature of the application.
